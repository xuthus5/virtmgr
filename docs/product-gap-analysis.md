# VirtMgr 产品差距分析与单机精品路线筛选

> 状态：`SH-01` 至 `SH-09`、`SH-11` 至 `SH-14` 以及单机边界中的热插拔、标签/备注/负责人、历史指标和基础告警已实现；`SH-10` 备份校验和夏令时处理按当前产品决定暂不实施。
> 日期：2026-11-13。
> 目标：以“单机精品 KVM/libvirt 管理平台”为当前产品定位，对比主流管理工具，区分值得优化的单机能力与暂不建议投入的平台级能力。

## 1. 结论

VirtMgr 当前更接近“现代化、Web 化的 Cockpit / virt-manager 增强版”，而不是 Proxmox VE、oVirt、Harvester、XCP-ng 或 OpenStack 这类平台级产品。

当前优势：

- 单二进制交付，部署和升级路径简单。
- 单机虚拟机日常运维闭环较完整：创建、生命周期、详情、VNC/串口控制台、快照、克隆和冷备份。
- 本地账号、Argon2id、CSRF、只读模式、登录限流和写操作审计等安全基础较完整。
- 模板预填、Cloud-init、PCI/USB 直通、任务中心、SSE 事件和备份中心形成了明确产品特色。
- 对单台宿主机而言，VM 交互、审计和备份体验强于 Cockpit/virt-manager 的默认组合。

当前主要短板：

- 镜像/真模板、磁盘和网卡热插拔、Guest Agent 深度集成、在线备份、历史指标和通知等单机高级能力不足。
- 身份联合、细粒度 RBAC、API Token、OpenAPI 和自动化生态偏弱。
- 与平台级产品相比，缺多主机、集群、迁移、HA、共享存储、SDN 和多租户；这些属于产品定位差异，不应零散补齐。

## 2. 对标坐标

| 工具 | 主要定位 | VirtMgr 相对差异 |
|---|---|---|
| Cockpit / cockpit-machines | 单机 Linux 主机管理 | VirtMgr 的虚拟机交互、审计、备份和模板更强；主机终端、服务、日志、软件更新、防火墙和存储挂载更弱 |
| virt-manager | 单机 libvirt 桌面客户端 | VirtMgr 有 Web、多用户、审计和备份；virt-manager 的硬件建模、SPICE、USB 重定向和迁移能力更完整 |
| Proxmox VE | 单机到集群的虚拟化平台 | VirtMgr 更轻量；缺集群、HA、迁移、共享存储、SDN、企业备份和成熟 API |
| oVirt | 企业虚拟数据中心 | 缺数据中心/集群/资源池/调度策略/细粒度权限/镜像治理 |
| XCP-ng + Xen Orchestra | XenServer 系虚拟化平台 | hypervisor 不同；缺资源池、迁移、HA 和集中备份生态 |
| Harvester | 基于 Kubernetes 的 HCI | 缺多节点、分布式存储、HA、Kubernetes 集成和镜像治理 |
| OpenStack | 多租户云操作系统 | 不在一个产品层级；缺多租户、配额、网络/存储编排和完整 API 生态 |
| Incus / LXD | 容器和虚拟机统一管理 | 缺镜像驱动、项目/profile、集群、远程 API 和容器工作负载 |

## 3. 当前能力边界

当前实现可以直接确认的边界：

- 一个 VirtMgr 实例连接一个 libvirt 端点，不支持多主机清单和迁移。
- 虚拟机模板是创建参数预设，不包含系统盘镜像。
- 创建虚拟机支持 BIOS/UEFI、Secure Boot、vCPU、内存、磁盘路径/格式、磁盘总线、网卡型号、启动顺序、活跃网络、ISO、Cloud-init 和 autostart。
- 支持 VNC 和串口控制台，不支持 SPICE。
- 支持磁盘扩容，以及数据磁盘和网卡的热附加/移除；系统盘和仍在使用的卷不允许移除。
- 支持 PCI/USB 主机设备直通，不支持客户端 USB 重定向。
- 快照支持创建、回滚、删除、固定间隔或每日时刻保留策略，不提供内存快照和 Guest Agent 静默；每日时刻使用服务端本地时区，不额外处理夏令时。
- 备份是关机状态下的冷全量备份，只支持 `file` 后端磁盘，恢复为新虚拟机；支持固定间隔或每日时刻调度、失败重试和任务 SSE 状态快照，不做备份内容自动校验。
- 存储池可在应用内创建的类型只有目录池；已有其他 libvirt 存储池可以读取。
- 网络创建支持 NAT/isolated、IPv4 和 DHCP；静态 DHCP 主机支持单条和 CSV 批量导入/导出，不提供桥接、VLAN、IPv6、SR-IOV、OVS 和安全组管理。
- 指标来自当前采样和上一次采样差值，并提供每分钟采样、保留 7 天的历史趋势、Prometheus `/metrics` 和 CPU/内存阈值告警 Webhook。
- 虚拟机支持标签、备注和负责人元数据，以及列表筛选、浏览器本地收藏和常用筛选持久化。
- 审计支持 JSON/CSV 导出、时间/目标过滤和可配置保留期清理；SQLite 数据库支持在线导出。
- API 使用 Cookie + CSRF，没有长期 API Token、实际 OpenAPI 文件、管理 CLI 或 IaC Provider。

## 4. 全量差距清单

### 4.1 单机核心能力

- `GAP-01 镜像库与真模板`：当前模板是配置预设；主流工具提供 OS 镜像目录、校验和、Cloud image、链接克隆和全量克隆。价值高，成本高。
- `GAP-02 虚拟机导入与格式迁移`：当前可从已有磁盘路径创建；缺 OVA、VMDK、VHDX、qcow2 上传、转换、校验和导入，也没有磁盘级导出/OVA 导出。价值中高，成本高。
- `GAP-03 磁盘和网卡热插拔`：已支持数据磁盘和网卡热附加/移除、系统盘保护；缺网卡型号修改、磁盘跨池迁移和更完整的取消/回滚语义。价值高，成本中。
- `GAP-04 高级硬件建模`：缺 vTPM、启动顺序、machine type、CPU model/topology、NUMA、hugepages、watchdog、RNG、vGPU/mdev 和 SR-IOV VF 的 GUI 管理。价值中高，成本中高。
- `GAP-05 控制台能力`：当前只有 VNC/串口；缺 SPICE、音频、客户端 USB 重定向、多显示器和文件传输。价值取决于是否服务 Windows/VDI，成本中高。
- `GAP-06 Guest Agent 深度集成`：当前主要读取 Agent 状态、IP 和主机名；缺 freeze/thaw、静默快照、Agent 关机、文件复制、客户机内执行、密码重置、时间同步和 trim。价值高，成本中。
- `GAP-07 快照成熟度`：缺内存状态快照、Guest Agent 静默、快照链可视化、合并/consolidation 和孤儿链清理；已支持固定间隔/每日时刻策略。价值中高，成本高。
- `GAP-08 备份成熟度`：缺在线一致性备份、增量备份、原地恢复、内存状态、S3/SFTP/远端仓库、加密、压缩、去重、自动校验、GFS 保留和跨主机复制。价值高，成本高。
- `GAP-09 Cloud-init 与 OS 定制`：当前支持 NoCloud user-data、network-config 和 vendor-data，并支持 Netplan v2 DHCP/静态 IPv4/IPv6；缺 config drive、执行结果回传、Windows Sysprep 和 OS profile。价值中高，成本中。
- `GAP-10 存储类型与管理深度`：应用内创建只支持目录池；缺 NFS、LVM、ZFS、iSCSI、Ceph RBD、Gluster 专用流程，以及卷克隆、卷迁移、格式转换、下载、QoS、TRIM 和 SMART。价值高，成本高。
- `GAP-11 网络广度`：当前主要管理 NAT/isolated、IPv4 和 DHCP；缺桥接、bond、VLAN、IPv6/RA、macvtap、SR-IOV、OVS、VXLAN/SDN、端口转发、安全组、防火墙和 QoS。价值高，成本高。
- `GAP-12 虚拟机组织能力`：已支持标签、备注和负责人；缺文件夹、资源分组和自定义字段。价值中，成本低到中。

### 4.2 团队化、安全与 API

- `GAP-13 SSO 与多因素认证`：当前只有本地账号；缺 LDAP/AD、OIDC、SAML 和 MFA/TOTP。单机单人场景价值较低，团队共用时价值高，成本中。
- `GAP-14 细粒度 RBAC 与配额`：当前是三个全局角色；缺按主机、虚拟机、存储池、网络分权，以及项目、租户、所有权和资源配额。价值高，成本中高。
- `GAP-15 API Token、OpenAPI 与 IaC`：缺长期 API Token、作用域、OpenAPI 契约、CLI、SDK、Ansible/Terraform Provider。价值高，成本中。
- `GAP-16 Webhook 与事件订阅`：当前 SSE 主要服务前端；缺外部 Webhook、过滤、签名、重试和订阅管理。价值中，成本中。
- `GAP-17 账号生命周期`：已支持自助改密、管理员重置密码、会话列表和撤销其他会话；缺密码过期/历史和 MFA。价值中，成本低到中。
- `GAP-18 审计合规能力`：已支持审计导出、时间/目标过滤和保留期配置；缺 Syslog/Webhook 转发和不可变保留。价值中，成本低到中。
- `GAP-19 VirtMgr 自身备份与升级`：已支持 SQLite 在线导出和版本/提交/构建时间展示；缺升级前自动备份、恢复向导、版本检查和原地升级流程。价值中高，成本中。
- `GAP-20 官方容器化部署`：已提供多阶段镜像和 Compose 示例；未提供 Helm、Kubernetes Operator 和镜像发布流水线。价值中，成本低到中。

### 4.3 运维与可观测性

- `GAP-21 历史指标与容量趋势`：已支持宿主机和运行中 VM 的每分钟采样、7 天历史趋势；缺磁盘 IOPS/延迟历史、文件系统使用率、长期趋势和容量预测。价值中高，成本中。
- `GAP-22 告警与通知`：已支持 CPU/内存阈值、持续时间和 Webhook；缺邮件、Slack/Teams、PagerDuty、静默和升级策略。价值高，成本中。
- `GAP-23 外部监控集成`：已提供 Prometheus 文本 `/metrics`；缺 OpenTelemetry、Syslog/SNMP 导出和标准告警对接。价值中高，成本中。
- `GAP-24 任务引擎成熟度`：已支持任务 SSE 状态快照和失败备份重试；缺取消、断点恢复、优先级、全局队列和可配置并发。价值中，成本中。
- `GAP-25 调度能力`：快照和备份已支持固定间隔或服务端本地时区的每日时刻；按产品决定不处理夏令时，缺 cron、维护窗口、GFS 保留和任务互斥策略。价值中，成本低到中。
- `GAP-26 宿主机管理`：缺 Web 终端、服务/进程、系统日志、软件更新、防火墙、SELinux、磁盘挂载、SMART、传感器和主机网络配置。与 Cockpit 竞争时重要，但建议优先集成而不是全部重做。价值中，成本中高。
- `GAP-27 大规模清单与服务端查询`：缺服务端分页、排序、复杂过滤和大规模批量任务吞吐验证。单机少量虚拟机场景价值有限。价值中低，成本中。
- `GAP-28 UI 国际化`：当前界面以中文为主；缺完整 i18n 资源和语言切换。价值取决于是否面向国际用户，成本中。

### 4.4 平台级与战略级能力

- `GAP-29 多主机/集群管理`：当前一个实例固定连接一个 libvirt 端点；缺 host registry、agent、中心化清单和多集群视图。
- `GAP-30 迁移与维护模式`：缺在线迁移、离线迁移、维护模式、主机疏散、回迁和迁移预检。
- `GAP-31 HA、调度与反亲和`：缺故障自动重启、HA 仲裁、放置策略、反亲和、资源预留和集群级自动恢复。
- `GAP-32 共享存储、复制与容灾`：缺共享存储模型、存储复制、跨主机快照、异地备份和灾难恢复。
- `GAP-33 多租户云平台语义`：缺项目、租户、配额、网络隔离、镜像所有权、用量和租户级 API。
- `GAP-34 多虚拟化与容器工作负载`：当前只管理 KVM/QEMU/libvirt；缺 Xen、VMware、Hyper-V、LXC/容器工作负载和统一迁移入口。

## 5. 单机精品定位下的筛选

### 5.1 评估口径

- 成本 `S`：主要改动集中在单个模块、前端表单或现有 API，通常不需要架构调整。
- 成本 `M`：需要新增数据表字段、跨 app/http/platform 改动或较多测试，但仍属于现有单机架构。
- 成本 `L`：需要新的存储/备份/调度体系，或跨模块平台能力。
- 价值只按当前“单机精品”定位评估，不按多集群或云平台价值评估。

### 5.3 边界候选：成本略高但仍属单机精品范围

- `GAP-03` 磁盘/网卡热插拔：价值高，成本 M。需要补齐 libvirt live/config XML、状态校验和回滚测试。
- `GAP-06` Guest Agent freeze/thaw 和 Agent 关机：价值高，成本 M。需要处理 Agent 不可用降级和任务一致性。
- `GAP-12` 标签、备注、负责人：价值中高，成本 S-M；若按设计写入域 XML metadata，需增加 XML 解析、写回和重建数据库后的恢复测试。
- `GAP-15` API Token 和 OpenAPI：价值高，成本 M；单机自动化场景值得评估，但应避免先做一个无法撤销和无作用域的长期 token。
- `GAP-21` 历史指标：价值中高，成本 M；可以先做进程内短期环形缓冲或 SQLite 轻量采样，不必直接引入 Prometheus/TimescaleDB。
- `GAP-22` 基础告警：价值高，成本 M；先做 CPU/内存/存储/VM 状态阈值和 Webhook，再评估邮件和外部值班平台。
- `GAP-01` 镜像库与真模板：价值高，成本 M-L；如果目标用户经常批量部署操作系统，应作为下一阶段核心方向。
- `GAP-08` 在线/增量备份和远端仓库：价值高，成本 L；需要单独的备份架构设计，不建议作为零散小功能实现。

### 5.4 单机定位下不建议优先投入

- `GAP-29` 到 `GAP-34`：多主机、集群、迁移、HA、共享存储容灾、多租户、多 hypervisor 和容器工作负载都会改变现有架构和产品定位。
- `GAP-26` 宿主机全面管理：如果只是补齐单机运维，优先考虑与 Cockpit 集成或跳转，而不是重做终端、服务、包管理和防火墙。
- `GAP-28` 完整国际化：只有明确面向国际用户时再做，否则会带来大量非核心改动。
- 完整 SDN、OpenStack 式配额/计费、完整 VDI/SPICE 生态：不建议在“单机精品”阶段追求。

## 6. 已完成批次与下一轮建议

第一轮 `SH-01` 至 `SH-05` 和第二轮 `SH-06` 至 `SH-09`、`SH-11` 至 `SH-14` 已完成。第二轮同时补齐了边界候选中的磁盘/网卡热插拔、VM 标签/备注/负责人、历史指标、基础告警，以及 Cloud-init network-config/vendor-data 和 Netplan v2。

按当前“单机精品”定位，下一轮建议按以下顺序选择性投入：

1. `GAP-15`：API Token、作用域和 OpenAPI 契约，提升自动化与集成能力。
2. `GAP-01`：镜像库与真模板，解决批量部署操作系统时的核心效率问题。
3. `GAP-06`：Guest Agent freeze/thaw、静默快照和 Agent 关机，提升数据一致性。
4. `GAP-10`：NFS/LVM/ZFS 等存储池创建和卷生命周期，补齐单机存储管理。
5. `GAP-19`：升级前自动备份、恢复向导和版本检查，完善单机升级闭环。

明确不进入当前范围：备份内容自动校验、夏令时特殊处理、多主机/集群、迁移、HA、共享存储容灾、多租户和多 hypervisor。

## 7. 已实施能力与 EARS 验收基线

以下实现均保持 libvirt 为基础设施事实来源，并沿用 Operator/Admin 权限、CSRF、全局只读和审计约束。

- `SH-01`：当 Operator 或 Admin 创建虚拟机并提供磁盘总线、网卡型号或启动顺序时，系统应校验枚举值并在域 XML 中生成对应设备；未提供时应保持 `virtio`、`virtio`、`auto` 的向后兼容默认值，且 `cdrom-first` 必须提供 ISO。
- `SH-02`：当 Operator 或 Admin 向活跃存储池上传 `.iso`、`.qcow2` 或 `.raw` 文件时，系统应按扩展名选择格式、流式写入 libvirt 存储卷、更新任务进度并在成功后返回刷新后的卷元数据；失败时应删除未完成卷并记录失败审计。
- `SH-03`：当虚拟机正在运行时，系统应在详情指标中返回可写数据盘的读写吞吐、IOPS 以及各网卡的收发速率；计数器重置或首次采样时应降级为 0，而不是产生异常值。
- `SH-04`：当管理员按动作、结果、目标 ID 或时间范围筛选审计日志时，系统应返回匹配记录；当管理员请求 JSON 或 CSV 导出时，系统应生成受类型声明的附件、限制最多 50,000 条、对 CSV 公式注入进行防护，并记录 `audit.export`。
- `SH-05`：当本地用户提交正确的当前密码和新密码时，系统应更新 Argon2id 哈希、保留当前会话并撤销其他会话；当管理员重置其他账号密码时，系统应撤销目标账号全部会话；会话列表不得暴露 token 哈希，用户不得通过重置接口修改自己的密码。
- `SH-06`：当管理员请求数据库在线导出时，系统应使用 SQLite `VACUUM INTO` 生成一致性副本，以附件形式返回且不阻塞正常请求，并记录 `system.database.export` 成功或失败审计。
- `SH-07`：当 Prometheus 抓取 `/metrics` 时，系统应返回宿主机 CPU、内存和网络吞吐的文本格式指标；指标采集失败时不得返回伪造的成功值。
- `SH-08`：当任务中心订阅 SSE 时，系统应周期性发送最近任务快照并在断线后允许浏览器重连；当 Operator 或 Admin 重试失败或中断的 `vm.backup` 任务时，系统应创建新的任务记录并保留原任务历史，其他任务类型应拒绝重试。
- `SH-09`：当 Operator 或 Admin 为快照策略或备份计划选择 `daily` 时，系统应校验 `HH:MM` 时刻并按服务端本地时区计算下一次执行；选择 `interval` 时应保持原有固定间隔语义。按产品决定，系统不针对夏令时做额外偏移。
- `SH-11`：当管理员设置 1 至 3650 天的审计保留期时，系统应持久化设置；服务启动时和每 6 小时应删除早于保留期的审计记录，并在实际删除后记录 `audit.retention.cleanup`。
- `SH-12`：当用户导出静态 DHCP 主机时，系统应返回包含 `mac,ip,name` 的 CSV 附件；当 Operator 或 Admin 导入 CSV 或 JSON 时，系统应先校验全部条目，跳过完全相同的重复项，冲突时不得部分写入，成功后记录 `network.dhcp.host.import` 审计。
- `SH-13`：当用户修改虚拟机状态、标签或负责人筛选时，系统应在浏览器本地保存筛选；用户可收藏或取消收藏虚拟机并只看收藏。本地存储损坏时应安全回退到默认筛选，不影响虚拟机列表读取。
- `SH-14`：当用户使用官方 Compose 构建镜像时，容器应以非特权用户运行，挂载 libvirt socket 和持久化数据目录，通过环境变量配置监听地址、数据库、只读模式和管理员密码；镜像应包含运行时 libvirt 库和健康检查。
- `GAP-03 热插拔`：当虚拟机运行且用户附加 qcow2/raw 数据磁盘或网卡时，系统应更新运行配置和持久配置并采集配置版本；移除磁盘时应拒绝系统盘和在用卷，移除网卡时应拒绝不存在的设备。
- `GAP-09 Cloud-init`：当用户提供 user-data、network-config 或 vendor-data 时，系统应将全部文件写入 NoCloud ISO；Netplan v2 应支持 DHCP 和静态 IPv4/IPv6 地址、网关和 DNS，非法地址不得静默生成配置。
- `GAP-12 组织能力`：当 Operator 或 Admin 更新虚拟机标签、备注或负责人时，系统应持久化元数据并记录 `vm.metadata.update`；删除虚拟机时应清理对应元数据，列表查询应支持标签、负责人和关键字过滤。
- `GAP-21 历史指标`：当服务运行时，系统应每分钟采样宿主机和运行中虚拟机指标并保留 7 天；查询时间范围过长或样本过多时应拒绝或限制请求，不得无界读取。
- `GAP-22 基础告警`：当启用的 CPU/内存规则超过阈值并持续达到配置时长时，系统应进入 `pending`/`firing` 状态并按配置调用 Webhook；恢复后应记录恢复状态。Webhook 失败不得阻塞指标采样主循环。
