# VirtMgr 产品差距分析与单机精品路线筛选

> 状态：`SH-01` 至 `SH-09`、`SH-11` 至 `SH-16`、`NB-01`、`NB-02`、`NB-04`、`NR-01`、`NR-02`、`NR-03`、`NR-05` 至 `NR-09`、`NX-01`、`NX-02`、`NX-03`、`NX-09`、`NX-11` 至 `NX-18` 已实现。最近一轮补齐多架构/机型能力适配、链接克隆展平、vTPM 2.0、关机态磁盘跨池迁移、运行中虚拟机在线一致性备份，以及数据面操作崩溃恢复和资源租约互斥。`NR-04` 升级前预检安全包、`SH-10` 备份校验、夏令时处理和通知中心扩展按当前产品决定不实施。
> 日期：2026-11-18。
> 目标：以“单机精品 KVM/libvirt 管理平台”为当前产品定位，对比主流管理工具，区分值得优化的单机能力与暂不建议投入的平台级能力。

## 1. 结论

VirtMgr 当前更接近“现代化、Web 化的 Cockpit / virt-manager 增强版”，而不是 Proxmox VE、oVirt、Harvester、XCP-ng 或 OpenStack 这类平台级产品。

当前优势：

- 单二进制交付，部署和升级路径简单。
- 单机虚拟机日常运维闭环较完整：创建、生命周期、详情、VNC/串口控制台、快照、克隆、冷备份和在线一致性备份。
- 本地账号、Argon2id、CSRF、只读模式、登录限流、带作用域的 API Token、OpenAPI 契约和写操作审计等安全与自动化基础较完整。
- 模板预填、Cloud-init、PCI/USB 直通、镜像库、任务取消、SSE 事件和备份中心形成了明确产品特色。
- 对单台宿主机而言，VM 交互、审计和备份体验强于 Cockpit/virt-manager 的默认组合。

当前主要短板：

- 镜像库已支持已有卷登记、QCOW2/RAW 上传、全量克隆和同存储池 qcow2 链接克隆；存储页还可将空闲 qcow2/raw 卷转换格式、复制到其他活跃池，并把空闲链接克隆展平为独立卷。关机虚拟机支持带引用切换的磁盘跨池迁移，运行中虚拟机支持外部磁盘快照在线备份。内存快照、NUMA/hugepages 和更完整的硬件建模仍需补强。
- 身份联合、细粒度 RBAC、CLI、SDK 和 IaC Provider 偏弱；告警通知仅保留现有规则级 Webhook。
- 与平台级产品相比，缺多主机、集群、迁移、HA、共享存储、SDN 和多租户；这些属于产品定位差异，不应零散补齐。

## 2. 对标坐标

| 工具 | 主要定位 | VirtMgr 相对差异 |
|---|---|---|
| Cockpit / cockpit-machines | 单机 Linux 主机管理 | VirtMgr 的虚拟机交互、审计、备份和模板更强；主机终端、服务、日志、软件更新、防火墙和存储挂载更弱 |
| virt-manager | 单机 libvirt 桌面客户端 | VirtMgr 有 Web、多用户、审计和备份；virt-manager 的硬件建模、SPICE、USB 重定向和迁移能力更完整 |
| Proxmox VE | 单机到集群的虚拟化平台 | VirtMgr 更轻量；缺集群、HA、迁移、共享存储、SDN、企业备份和成熟 API |
| oVirt | 企业虚拟数据中心 | 缺数据中心/集群/资源池/调度策略/细粒度权限/镜像治理 |
| XCP-ng + Xen Orchestra | XenServer 系虚拟化平台 | hypervisor 不同；缺资源池、迁移、HA 和集中备份生态 |
| Harvester | 基于 Kubernetes 的 HCI | 缺多节点、分布式存储、HA、Kubernetes 集成和镜像治理 |
| OpenStack | 多租户云操作系统 | 不在一个产品层级；缺多租户、配额、网络/存储编排和完整 API 生态 |
| Incus / LXD | 容器和虚拟机统一管理 | 缺镜像驱动、项目/profile、集群、远程 API 和容器工作负载 |

## 3. 当前能力边界

当前实现可以直接确认的边界：

- 一个 VirtMgr 实例连接一个 libvirt 端点，不支持多主机清单和迁移。
- 虚拟机模板仍是创建参数预设，但可绑定镜像库条目；模板本身不复制或拥有镜像。
- 镜像库支持上传 qcow2/raw 文件，或登记已有存储卷及其操作系统元数据、容量和按需刷新的 SHA-256；移除条目不会删除底层卷。创建虚拟机支持全量克隆，以及同存储池 qcow2 镜像的链接克隆；链接克隆基础卷被引用时禁止删除。存储页支持空闲卷的 qcow2/raw 格式转换和跨池复制，源卷保留，虚拟机引用不会自动切换。
- 创建虚拟机支持 BIOS/UEFI、Secure Boot、vCPU、内存、已有磁盘/镜像克隆、磁盘总线、网卡型号、启动顺序、活跃网络、ISO、Cloud-init 和 autostart。
- 已有持久虚拟机可在关机或异常停止状态从活跃存储池挂载或替换安装 ISO；操作只改写 CD-ROM 设备，保留 cloud-init 介质和全部存储卷，并切换为光盘优先启动。弹出 ISO 后恢复磁盘优先启动。
- 支持 VNC 和串口控制台，不支持 SPICE。
- 支持磁盘扩容，以及数据磁盘和网卡的热附加/移除；系统盘和仍在使用的卷不允许移除。
- 支持 PCI/USB 主机设备直通，不支持客户端 USB 重定向。
- 快照支持创建、回滚、删除、固定间隔或每日时刻保留策略和 Guest Agent 静默标记追溯，不提供内存快照；每日时刻使用服务端本地时区，不额外处理夏令时。
- 备份是关机状态下的冷全量备份，只支持 `file` 后端磁盘，恢复为新虚拟机；支持固定间隔或每日时刻调度、失败重试和任务 SSE 状态快照，不做备份内容自动校验。
- 任务中心支持 `vm.clone`、备份相关任务、磁盘跨池迁移、存储卷上传等安全检查点取消；同一资源上的可取消任务串行执行。取消不会强杀进程，可能在下一个检查点前保留中间文件，UI 会明确提示。
- 存储池可在应用内创建目录池、NFS `netfs` 池和 LVM `logical` 池；其他 libvirt 存储池可以读取。LVM 池只允许创建 raw 块卷且不接受文件上传。
- 网络创建支持 NAT/isolated、外部桥接、IPv4 和 DHCP；外部桥接复用宿主机已有 Linux 网桥并由上游网络提供地址/DHCP，静态 DHCP 主机支持单条和 CSV 批量导入/导出。不提供网桥创建、VLAN、IPv6、SR-IOV、OVS 和安全组管理。
- 指标来自当前采样和上一次采样差值，并提供每分钟采样、保留 7 天的历史趋势、Prometheus `/metrics` 和 CPU/内存/客户机文件系统阈值告警 Webhook。
- 虚拟机支持标签、备注和负责人元数据，以及列表筛选、浏览器本地收藏和常用筛选持久化。
- Guest Agent 支持固定动作、文件/密码/SSH 公钥/进程/登录用户管理、systemd 服务只读诊断、期望状态和连通性历史；不提供通用任意命令执行。
- 全局搜索覆盖虚拟机、网络、存储池、存储卷、镜像、模板、任务和静态页面入口。
- 审计支持 JSON/CSV 导出、时间/目标过滤和可配置保留期清理；SQLite 数据库支持在线导出。
- API 支持浏览器 Cookie + CSRF 和长期 Bearer API Token。Token 按用户签发，支持只读/读写作用域、有效期和即时撤销；明文仅在创建响应中返回一次。OpenAPI 3.1 契约位于 `GET /api/v1/openapi.json`，覆盖全部已挂载路由、主要请求/响应模型、错误响应和示例，并受契约测试保护。管理 CLI、SDK 和 IaC Provider 仍未实现。

## 4. 全量差距清单

### 4.1 单机核心能力

- `GAP-01 镜像库与真模板`：已实现镜像登记、QCOW2/RAW 上传、容量/校验值刷新、模板绑定镜像、创建时全量克隆和同存储池 qcow2 链接克隆；存储卷支持空闲态格式转换、跨池复制和链接克隆展平，仍缺虚拟机引用自动重写和更完整的 Cloud image 治理。价值高，成本高。
- `GAP-02 虚拟机导入与格式迁移`：已支持从活跃存储池选择或上传 QCOW2/RAW 系统盘，以及 ISO 安装介质；ISO 导入会创建空白 QCOW2 系统盘并以光盘优先启动。来源卷保留；缺 OVA/OVF、VMDK、VHDX、异构格式转换和磁盘/OVA 导出。按单机精品定位，异构图导入与格式转换不在当前范围。价值中，成本高。
- `GAP-03 磁盘和网卡热插拔`：已支持数据磁盘和网卡热附加/移除、系统盘保护，以及关机/异常停止虚拟机的磁盘跨池复制和持久域引用原子切换；缺网卡型号修改和更完整的取消/回滚语义。价值高，成本中。
- `GAP-04 高级硬件建模`：已支持 vTPM 2.0、启动顺序、宿主机能力驱动的 machine type、CPU model/topology、UEFI 与 Secure Boot；缺 NUMA、hugepages、watchdog、RNG、vGPU/mdev 和 SR-IOV VF 的 GUI 管理。价值中高，成本中高。
- `GAP-05 控制台能力`：当前只有 VNC/串口；缺 SPICE、音频、客户端 USB 重定向、多显示器和文件传输。价值取决于是否服务 Windows/VDI，成本中高。
- `GAP-06 Guest Agent 深度集成`：已实现通道探测、连接/无响应状态、诊断建议、时区/路由、操作系统/网络/文件系统信息、能力矩阵、Agent 关机/重启、时间同步、按文件系统 TRIM、关机态补齐通道、手动静默快照、受限文件读写、密码重置、SSH 公钥、登录用户、固定命令进程管理、systemd 服务只读诊断和期望状态健康历史；仍不提供通用任意命令执行。价值高，成本中高。
- `GAP-07 快照成熟度`：缺内存状态快照、快照链可视化、合并/consolidation 和孤儿链清理；已支持静默标记追溯和固定间隔/每日时刻策略。价值中高，成本高。
- `GAP-08 备份成熟度`：已支持关机冷备份和运行中虚拟机的外部磁盘快照在线备份，可选择 Guest Agent 静默并记录一致性/vTPM 状态；缺增量备份、原地恢复、内存状态、S3/SFTP/远端仓库、加密、压缩、去重、自动校验、GFS 保留和跨主机复制。价值高，成本高。

### 4.2 团队化、安全与 API

- `GAP-13 SSO 与多因素认证`：当前只有本地账号；缺 LDAP/AD、OIDC、SAML 和 MFA/TOTP。单机单人场景价值较低，团队共用时价值高，成本中。

- `GAP-15 API Token、OpenAPI 与 IaC`：已实现长期 API Token、read/write 作用域、撤销、Bearer 认证和覆盖全部已挂载路由的 OpenAPI 3.1 契约；仍缺管理 CLI、SDK、Ansible/Terraform Provider。价值高，成本中。
- `GAP-16 外部事件订阅`：当前 SSE 主要服务前端，告警仅使用规则级 Webhook。按产品决定不扩展外部事件订阅、通知渠道管理、签名、重试历史和订阅管理。

- `GAP-18 审计合规能力`：已支持审计导出、时间/目标过滤和保留期配置；缺 Syslog/Webhook 转发和不可变保留。价值中，成本低到中。
- `GAP-19 VirtMgr 自身备份与升级`：已支持 SQLite 在线导出和版本/提交/构建时间展示；按当前产品决定不实施升级前预检安全包，仍缺恢复向导、版本检查和原地升级流程。价值中高，成本中。

- `GAP-24 任务引擎成熟度`：已支持任务 SSE 状态快照、失败备份重试、安全检查点取消、终态保护和同资源互斥；缺断点恢复、优先级、全局队列和可配置并发。价值中，成本中。

- `GAP-28 UI 国际化`：当前界面以中文为主；缺完整 i18n 资源和语言切换。价值取决于是否面向国际用户，成本中。

### 4.4 平台级与战略级能力

- `GAP-29 多主机/集群管理`：当前一个实例固定连接一个 libvirt 端点；缺 host registry、agent、中心化清单和多集群视图。
- `GAP-30 迁移与维护模式`：缺在线迁移、离线迁移、维护模式、主机疏散、回迁和迁移预检。

- `GAP-32 共享存储、复制与容灾`：缺共享存储模型、存储复制、跨主机快照、异地备份和灾难恢复。
- `GAP-33 多租户云平台语义`：缺项目、租户、配额、网络隔离、镜像所有权、用量和租户级 API。

## 5. 单机精品定位下的筛选

### 5.1 评估口径

- 成本 `S`：主要改动集中在单个模块、前端表单或现有 API，通常不需要架构调整。
- 成本 `M`：需要新增数据表字段、跨 app/http/platform 改动或较多测试，但仍属于现有单机架构。
- 成本 `L`：需要新的存储/备份/调度体系，或跨模块平台能力。
- 价值只按当前“单机精品”定位评估，不按多集群或云平台价值评估。

### 5.2 低成本、中高价值候选

| 编号 | 优化项 | 对应 GAP | 成本 | 价值 | 低成本原因 | 状态 |
|---|---|---|---|---|---|---|
| `SH-01` | 创建虚拟机时选择磁盘总线（virtio/sata/scsi）、网卡型号（virtio/e1000）和启动顺序 | GAP-04 | S | 中高 | 当前创建 XML 已集中生成，主要扩展 Spec、表单和测试 | 已实现 |
| `SH-02` | 支持上传 QCOW2/RAW 系统盘及 ISO 并从已有卷导入虚拟机；ISO 模式创建空白系统盘和只读光驱 | GAP-02 | S-M | 高 | 复用存储卷复制/创建、创建域、异步任务、审计和配置版本路径；不做 OVA/OVF 与格式转换 | 已实现 |

## 7. 已实施能力与 EARS 验收基线

以下实现均保持 libvirt 为基础设施事实来源，并沿用 Operator/Admin 权限、CSRF、全局只读和审计约束。

- `SH-01`：当 Operator 或 Admin 创建虚拟机并提供磁盘总线、网卡型号或启动顺序时，系统应校验枚举值并在域 XML 中生成对应设备；未提供时应保持 `virtio`、`virtio`、`auto` 的向后兼容默认值，且 `cdrom-first` 必须提供 ISO。
- `SH-02`：当 Operator 或 Admin 向活跃存储池上传 `.iso`、`.qcow2` 或 `.raw` 文件时，系统应按扩展名选择格式、流式写入 libvirt 存储卷、更新任务进度并在成功后返回刷新后的卷元数据；失败时应删除未完成卷并记录失败审计。
- `SH-03`：当虚拟机正在运行时，系统应在详情指标中返回可写数据盘的读写吞吐、IOPS 以及各网卡的收发速率；计数器重置或首次采样时应降级为 0，而不是产生异常值。
- `SH-04`：当管理员按动作、结果、目标 ID 或时间范围筛选审计日志时，系统应返回匹配记录；当管理员请求 JSON 或 CSV 导出时，系统应生成受类型声明的附件、限制最多 50,000 条、对 CSV 公式注入进行防护，并记录 `audit.export`。
- `SH-05`：当本地用户提交正确的当前密码和新密码时，系统应更新 Argon2id 哈希、保留当前会话并撤销其他会话；当管理员重置其他账号密码时，系统应撤销目标账号全部会话；会话列表不得暴露 token 哈希，用户不得通过重置接口修改自己的密码。
- `SH-06`：当管理员请求数据库在线导出时，系统应使用 SQLite `VACUUM INTO` 生成一致性副本，以附件形式返回且不阻塞正常请求，并记录 `system.database.export` 成功或失败审计。
- `SH-07`：当 Prometheus 抓取 `/metrics` 时，系统应返回宿主机 CPU、内存和网络吞吐的文本格式指标；指标采集失败时不得返回伪造的成功值。
- `SH-08`：当任务中心订阅 SSE 时，系统应周期性发送最近任务快照并在断线后允许浏览器重连；当 Operator 或 Admin 重试失败或中断的 `vm.backup` 任务时，系统应创建新的任务记录并保留原任务历史，其他任务类型应拒绝重试。
- `SH-09`：当 Operator 或 Admin 为快照策略或备份计划选择 `daily` 时，系统应校验 `HH:MM` 时刻并按服务端本地时区计算下一次执行；选择 `interval` 时应保持原有固定间隔语义。按产品决定，系统不针对夏令时做额外偏移。
- `SH-11`：当管理员设置 1 至 3650 天的审计保留期时，系统应持久化设置；服务启动时和每 6 小时应删除早于保留期的审计记录，并在实际删除后记录 `audit.retention.cleanup`。
- `SH-12`：当用户导出静态 DHCP 主机时，系统应返回包含 `mac,ip,name` 的 CSV 附件；当 Operator 或 Admin 导入 CSV 或 JSON 时，系统应先校验全部条目，跳过完全相同的重复项，冲突时不得部分写入，成功后记录 `network.dhcp.host.import` 审计。
- `SH-13`：当用户修改虚拟机状态、标签或负责人筛选时，系统应在浏览器本地保存筛选；用户可收藏或取消收藏虚拟机并只看收藏。本地存储损坏时应安全回退到默认筛选，不影响虚拟机列表读取。
- `SH-14`：当用户使用官方 Compose 构建镜像时，容器应以非特权用户运行，挂载 libvirt socket、持久化数据目录和只读的 `/etc/virtmgr/server.yaml`，通过 YAML 配置监听地址、数据库、只读模式和管理员密码；镜像应包含运行时 libvirt 库和健康检查。
- `NX-12`：当 Operator 或 Admin 创建或导入虚拟机时，系统应读取宿主机 libvirt capabilities 和 domain capabilities，校验架构、机型和 UEFI/Secure Boot；未指定架构时使用宿主机架构，不支持的组合应拒绝且不创建资源。
- `NX-13`：当用户展平空闲链接克隆时，系统应仅接受未被虚拟机或下游链接克隆引用的 qcow2 卷，创建独立 qcow2 目标卷并保留源卷；目标为 LVM logical 池时应拒绝。
- `NX-14`：当 Operator 或 Admin 迁移关机/异常停止持久虚拟机的可写数据盘时，系统应复制到目标活跃池、原子改写持久域引用并保留旧卷；复制或改写失败应删除目标卷，运行域、只读盘和临时域应拒绝。
- `NX-15`：当用户在创建或导入虚拟机时启用 vTPM 2.0，系统应仅在宿主 domain capabilities 声明 TPM 支持时允许提交，并生成对应架构的 `tpm-crb` 或 `tpm-tis` emulator 设备；虚拟机详情应回读 TPM 状态。
- `NX-16`：当 Operator 或 Admin 备份运行中持久虚拟机时，系统应选择在线模式，通过外部磁盘快照复制稳定基卷并保持虚拟机运行；请求静默时必须验证 Guest Agent，未启用的虚拟机不得以在线模式备份。备份应记录在线、静默、一致性及 vTPM 状态，且明确 vTPM 状态未保存。
- `NX-17`：当服务在备份、磁盘迁移、虚拟机导入、存储卷转换或链接克隆展平过程中退出时，系统应在开始提供写服务前读取持久化数据面操作日志，并结合当前活动/持久域 XML 和存储卷引用关系续做、完成、回滚或标记人工处理。系统只有在确认目标卷未被任何虚拟机引用时才能删除；在线备份只有在 live XML 已回切基础卷且备份 manifest、配置和全部磁盘产物完整时才能标记为成功。每个恢复结果应更新中断任务说明、结束操作日志并写入 `dataplane.recovery` 审计；需人工处理或恢复失败时，应阻塞对应虚拟机或目标存储卷的后续数据面操作。
- `NX-18`：当同一虚拟机或同一存储卷同时收到备份、快照、磁盘迁移、克隆、导入、恢复、磁盘扩容、格式转换或展平请求时，系统应通过资源租约互斥；克隆需要同时锁定源虚拟机和目标名称，存储卷转换/展平需要同时锁定源卷和目标卷，多锁必须按键排序原子获取且失败不得残留部分锁。冲突请求应返回 HTTP `409 OPERATION_CONFLICT`，不得创建任务或修改资源；任务成功、失败、取消或恢复结束后必须释放租约。进程重启后的陈旧内存租约不持久化，由 `NX-17` 依据操作日志重新协调。
- `GAP-03 热插拔`：当虚拟机运行且用户附加 qcow2/raw 数据磁盘或网卡时，系统应更新运行配置和持久配置并采集配置版本；移除磁盘时应拒绝系统盘和在用卷，移除网卡时应拒绝不存在的设备。
- `GAP-09 Cloud-init`：当用户提供 user-data、network-config 或 vendor-data 时，系统应将全部文件写入 NoCloud ISO；Netplan v2 应支持 DHCP 和静态 IPv4/IPv6 地址、网关和 DNS，非法地址不得静默生成配置。
- `GAP-12 组织能力`：当 Operator 或 Admin 更新虚拟机标签、备注或负责人时，系统应持久化元数据并记录 `vm.metadata.update`；删除虚拟机时应清理对应元数据，列表查询应支持标签、负责人和关键字过滤。
- `GAP-21 历史指标`：当服务运行时，系统应每分钟采样宿主机和运行中虚拟机指标并保留 7 天；查询时间范围过长或样本过多时应拒绝或限制请求，不得无界读取。
- `SH-15`：当用户读取 Guest Agent 状态时，系统应返回 `not_configured`、`disconnected`、`connected`、`unresponsive` 或 `error` 结构化状态，并在 15 秒内复用探测结果、合并并发请求；Agent 不可用不得导致状态接口失败。新建虚拟机默认生成 `org.qemu.guest_agent.0` channel；已有持久域仅在关机或异常停止状态允许补齐通道。仅当 Agent 已连接且能力矩阵声明支持时，系统才允许 Agent 关机、重启、时间同步、TRIM 和静默快照；静默快照不可用时必须拒绝而不是降级为普通快照。
- `SH-16`：当 Operator/Admin 在可写模式下操作 Guest Agent 时，系统应对文件、密码、SSH 公钥和进程动作执行固定接口、CSRF、只读、权限和能力校验；文件只允许绝对路径且单次不超过 1 MiB，进程只允许固定 `ps`/`kill` 命令并拒绝 PID 1；变更必须生成任务，审计不得包含密码、文件内容或完整 SSH 公钥。
- `NB-01`：当浏览器会话用户创建 API Token 时，系统应校验名称、read/write 作用域和 0 至 3650 天有效期，仅返回一次明文并只持久化哈希；当客户端使用 Bearer Token 时，系统应允许 read 作用域执行安全方法、write 作用域执行写方法，拒绝 Token 自行创建、列出或撤销 Token，并继续对浏览器写请求校验 CSRF。撤销、过期或用户被禁用后，Token 应立即失效；创建和撤销应写入不包含明文的审计。
- `NB-02`：当 Operator/Admin 登记已有 qcow2/raw 存储卷为镜像时，系统应保存来源池、卷、格式、容量和可选操作系统元数据；刷新时应回读容量并计算 SHA-256，移除时只删除登记而不删除底层卷，被模板引用时应拒绝移除。当用户从镜像创建虚拟机时，系统应复制来源卷为独立系统盘，禁止源卷与目标卷相同；克隆失败时不得留下新域或部分磁盘。模板可以绑定镜像，但不得因绑定而取得镜像所有权。
- `NB-04`：当 Operator/Admin 取消处于排队或运行状态且属于允许类型的任务时，系统应在前端确认后请求取消，并在下一个安全检查点停止执行；任务进入 `cancelled` 后不得再被成功/失败更新覆盖。系统应保证同一资源上的可取消任务串行执行，并拒绝取消已经进入终态、不可取消类型、缺少取消注册或只读模式下的任务。取消可能保留中间文件，UI 和文档不得承诺强制终止或自动回滚未完成的副作用。
- `GAP-22 基础告警`：当启用的 CPU/内存规则超过阈值并持续达到配置时长时，系统应进入 `pending`/`firing` 状态并按配置调用 Webhook；恢复后应记录恢复状态。Webhook 失败不得阻塞指标采样主循环。
- `NR-01`：当 Operator 或 Admin 为关机或异常停止的持久虚拟机从活跃存储池挂载 ISO 时，系统应确认卷为 `.iso`、替换已有非 cloud-init 安装光驱或新增光驱、保留 cloud-init 介质、设置光盘优先启动且不删除任何存储卷；运行中、临时虚拟机、非 ISO 卷和只读模式必须拒绝。
- `NR-02`：当 Operator 或 Admin 创建 NFS `netfs` 存储池时，系统应要求有效主机名、绝对导出路径和绝对挂载目标，拒绝混入 LVM 字段，并由 libvirt 管理池定义与启停；成功和失败均写入脱敏审计。
- `NR-03`：当 Operator 或 Admin 读取 Guest Agent 服务状态时，系统应只对支持 Guest Agent 的 Linux 客户机执行固定 `systemctl list-units --type=service` 只读查询，返回最多 500 个 unit 的 load/active/sub/description；不得提供启动、停止、重启或修改服务接口。
- `NR-05`：当监控采样运行时，系统应对已连接且运行中的虚拟机读取 Guest Agent 文件系统列表，以最高使用百分比作为 `guest_filesystem_percent` 参与现有阈值规则；Guest Agent 查询失败不得阻塞宿主机指标采集，通知仍只使用规则级 Webhook。
- `NR-06`：当用户读取 `GET /api/v1/openapi.json` 时，系统应返回有效 OpenAPI 3.1 文档，覆盖全部已挂载路由，并为每个操作提供唯一 `operationId`、标签、摘要和响应；路径参数必须声明，内部 `$ref` 必须可解析，契约测试应覆盖新增路由与主要请求/响应模型以防漂移。
- `NR-07`：当用户在全局搜索中输入资源关键字时，系统应在现有虚拟机、网络和存储池之外继续匹配活跃存储池中的卷、镜像、模板和任务，并在选择结果后跳转到对应页面；单个数据源失败不得阻止其他来源展示。
- `NR-08`：当 Operator 或 Admin 创建 LVM `logical` 存储池时，系统应要求有效卷组和 `/dev/` 绝对目标路径；该池中的新卷只能为 raw，文件上传必须拒绝，池启停、刷新和删除继续以 libvirt 为权威来源。
- `NR-09`：当 Operator 或 Admin 创建或编辑外部桥接网络时，系统应要求选择有效的宿主机 Linux 网桥，校验该接口存在、类型为 bridge 且未被其他 libvirt 网络占用；bridge 模式不得创建 libvirt IP 或 DHCP，网络生命周期仍以 libvirt 为权威来源。系统只接入已有网桥，不负责创建或修改宿主机网桥、VLAN、bond、OVS 或 SR-IOV。
- `NX-01`：当 Operator 或 Admin 在可写模式下请求在线扩展客户机文件系统时，系统应校验绝对挂载点、Guest Agent 连接状态和 `filesystemResize` 能力，仅允许 Linux 上由直接块设备承载的 ext4/xfs，使用固定路径的 `growpart` 与 `resize2fs`/`xfs_growfs` 扩展分区和文件系统，并以任务展示结果和写入脱敏审计；Windows、未连接 Agent、根文件系统、LVM、非直接块设备、容量未增长及只读模式必须明确拒绝，不得执行任意命令。
- `NX-02`：当 Operator 或 Admin 读取 Linux 客户机启动与故障诊断时，系统应仅通过 Guest Agent 执行固定路径的 `systemctl` 和 `journalctl` 查询，返回失败服务、最多 5 个失败服务日志尾部、内核告警、系统错误、OOM 事件、建议和命令错误，并限制日志为固定条数及最多 24 KiB；系统不得提供服务启停、配置修改或任意日志路径访问能力。
- `NX-03`：当 Operator 或 Admin 转换空闲 qcow2/raw 存储卷时，系统应校验角色、只读模式、源卷格式与占用状态、链接克隆引用、目标池活跃状态、目标名称/格式/扩展名、目标冲突和池容量，并通过异步任务在目标池创建目标格式卷；运行中虚拟机占用、被其他卷作为基础卷引用、链接克隆源卷、非法来源目标同名和只读模式必须拒绝。任务成功应保留源卷，失败应删除本次未完成的目标卷并记录失败审计。
- `NX-09`：当 Operator 或 Admin 修改持久虚拟机启动顺序时，系统应仅接受已存在的硬盘、光盘和网卡组成的唯一非空顺序，并清除设备级旧启动顺序；当修改 CPU 型号与拓扑时，系统应仅允许关机或异常停止状态，校验型号字符集及 sockets/cores/threads 乘积等于当前 vCPU 数。成功应回读持久配置、生成配置版本并写入审计；运行中、临时域、未知设备和拓扑不匹配必须拒绝。
- `NX-11`：当 Operator 或 Admin 设置可写磁盘吞吐/IOPS 或网卡入站/出站带宽时，系统应校验范围，网卡存在峰值或 burst 时必须提供平均值且峰值不低于平均值；运行中虚拟机应同时更新 live 和持久配置，关机虚拟机更新持久配置，全部为零时移除对应限制。成功后应回读 QoS、生成配置版本并写入审计；只读模式、越权、只读/光盘设备和不存在的磁盘或网卡必须拒绝。
- `NR-04` 当前不实施：系统不提供升级前安装包或预检安全包，也不应在本轮代码和文档中声称具备该能力。
